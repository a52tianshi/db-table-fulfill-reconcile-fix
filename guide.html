01 / 拓扑简单，状态分层

user_old → 可注入的分片路由 → user_new_shard_1 … user_new_shard_100

这是同一个逻辑数据集，不是 100 组独立业务表。Memory 在这个数据集内以 identifier 为唯一 key；同 key 的两端观测合并到一条记录，并保存目标分片。若未来支持多个逻辑数据集，再增加数据集命名空间。

老表逐表状态

每张表记录未开始、扫描中、缓存满暂停、扫描结束、失败。字段包括读取游标、安全游标、已读条数、批次范围和完成批次数。

新分片逐表状态

每个物理分片各有独立进度。按 key 批量查询不推进全表扫描游标。表扫描结束不代表候选已处理完。

Memory 逐条状态

key、两端数据及存在性、扫描/查询来源、目标分片、当前批次、初比结果、复核与修复状态。记录状态细，表状态保持简单。

02 / 批次流水线：攒起来，再访问 DB

批量扫描老表 → Memory 攒批 → 按分片归组批量查询新表 → 内存初比
疑似差异排队攒复核批次 → 业务事务内批量重读两端 → 重新分类
待插入批 / 待逐条更新记录 / 仅报警 → 批量插入或逐条更新 → 提交成功 → 释放缓存、推进安全进度
再逐分片批量扫描新表 → 批量查询老表 → 额外记录进入同一复核流水线
扫描批

一次读一页多条，避免每条 SELECT。每页有完整性和游标边界；可暂停以形成背压。

配对与复核批

同目标分片的多个 key 合并查询。内存先排除相等记录；仅疑似差异参加批量事务复核。

写入批

复核后按目标分片和操作种类归组，批量 INSERT / 逐条 UPDATE。更新每次只处理一个 key；具体 SQL 与事务由业务实现。

不是一次批量调用就一定只有一条 SQL。适配器可依据参数、报文和锁预算拆成若干语句，批量读取和批量插入减少 DB 交互；不支持批量更新，每条待更新记录仍独立执行一次 UPDATE。同一事务内可顺序更新多条，但这不是一条批量更新 SQL。

03 / 记录状态与批次状态

记录：等待配对 → 等待初比 → 初比相等完成 / 等待复核攒批
复核批就绪 → 事务内批量重读 → 等待批量插入 / 等待逐条更新 / 只报警 / 相等跳过
写入中 → 等待提交 → 提交完成 → 可回收

批次独立维护：攒批中 → 就绪 → 批量读取中 → 比较中 → 事务复核中 → 分类写入中 → 提交中 → 排空。失败时记录失败阶段，不能把 SQL 执行成功当作提交成功。

事务边界：“等待复核攒批”在事务外完成，不提前持锁。事务开始后批量重读、重新分类、插入或更新并提交；“等待插入/更新”是事务内部短暂状态，不能释放锁后长时间排队。跨事务执行须重新复核或使用版本条件写入并处理冲突。

两端存在性分别为 UNKNOWN（没加载）、PRESENT（读到）、ABSENT（完整查询确认不存在）。不能把尚未扫到、部分返回或超时当不存在。只在新表存在的记录始终保留并报警，不删除。

05 / 什么时候发批，什么时候停下来

  • 扫描批、配对批、复核批、写入批可分别配置条数、字节上限、SQL 参数预算、最大等待时间及事务时间预算；不是所有阶段必须同样大小。
  • 达到任一阈值就发批，扫描 EOF 时也发送尾批。满缓存则暂停扫描、优先排空现有记录。不能只等批满而无限等待；单个过大记录须明确报错或使用受限独立路径。
  • 按目标分片归组；不逐 key 查询全部 100 张表。路由规则或批量路由查询由调用方注入。若无法可靠路由，必须另设计批量索引或全量配对策略，不静默猜测。
  • 多分片批次可拆成多个受限事务。同一 key 的两端复核及相应写入必须使用业务提供的一致性边界；不能把多个事务误称为整批全局原子。
  • 批量失败不能把未知结果当全部成功；回滚可重试的事务，提交结果不确定则重读并幂等确认。部分分片已提交的结果保留，重试不重复累计业务成功事件。

06 / 完成与恢复

老表读完、所有新分片读完、缓存与候选批次排空、没有未决提交或告警，才算本轮完成。安全检查点仅在对应已读范围内所有结果完成后推进，不能越过仍在其他分片排队的记录。

Memory 有界，不能保留整轮全部 key 做历史去重。反向扫描可能重复遇到同 key，允许重新配对并幂等处理。路由正确性、唯一键约束及错误落片检测策略必须明确。

只报警模式不执行写入；仅新表存在永远只报警。持续并发修改需要快照、高水位、版本检查、CDC 或重跑；本轮完成不等于完整不停机迁移方案。持久化检查点和崩溃恢复仍是后续实现。

实际库的修复边界：Schema.KeyLess 必填，用于分块前统一主键锁序；Scan/Lookup/Lock 检测物理错片并返回 ErrMisrouted，不移动或删除。已提交批次先完整计数，再逐条通知；Warned 不是通知交付成功数，通知可能重复或遗漏。详见 README 和接口约定。
