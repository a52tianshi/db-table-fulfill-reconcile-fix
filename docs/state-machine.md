# 分片批量核对：状态机设计稿

一张 `user_old` 对应同结构的 `user_new_shard_1 … 100`。本稿定义下一版方案；现有 Go MVP 尚未实现分片路由、批量扫描及批量事务回调，不修改 Go 行为。[HTML](../guide.html) 提供 16 步离线演示。

## 状态归属

- 每张物理老表、新分片表各有独立的简单状态：未开始、扫描中、缓存满暂停、扫描结束、失败。取消由任务记录并停止推进，不能视作扫描结束。
- 每张表保存读取游标、安全游标、已读条数、当前批次 ID/范围、完成批次数及扫描边界。按 key 查询不推进扫描游标。
- Memory 属于逻辑数据集，以 identifier 为唯一 key，合并两端观测；记录数据、存在性、来源、目标分片、初比结果、处理阶段及所属批次。多数据集才增加命名空间。

## 写入能力约束

支持批量插入，不支持批量更新。UPDATE 每次只处理一个 key；同一复核事务可顺序执行多条单行 UPDATE，不能合并成一条批量更新语句。批量查询和复核仍然保留。

## 批量流水线

批量扫描老表 → Memory 攒批 → 路由并按分片批量查询新表 → 内存初比 → 差异进入待复核批次 → 事务内批量重读两端 → 按最新结果归组为插入批、逐条更新队列、报警或跳过 → 批量写入并提交 → 排空缓存并推进安全进度。

反向按分片批量扫描新表，批量查询老表，额外记录进入同一复核流程。仅新表存在始终保留并报警，绝不删除。只报警模式跳过所有写入。

## 记录状态

等待配对 → 等待初比 → 初比相等完成，或等待复核攒批 → 复核批就绪 → 事务复核中 → 等待批量插入 / 等待逐条更新 / 相等跳过 / 仅报警 → 写入中 → 等待提交 → 修复完成 → 可回收。

存在性单独记录 UNKNOWN / PRESENT / ABSENT。只有完整成功查询能确认 ABSENT；未扫到、部分返回和超时均不算不存在。任何阶段失败记录错误和原阶段，不宣称完成。

## 批次状态与事务

批次：攒批中 → 就绪 → 批量读取中 → 比较中 → 事务复核中 → 分类写入中 → 提交中 → 排空。

事务外积累复核批，不提前持锁。事务内重读、比较、按操作分组写入并提交。“等待插入/更新”只是同一事务内部短暂状态，不得释放锁后长期排队；跨事务执行须再次重读或版本条件写入。

业务注入批量事务回调，负责锁、缺失行插入竞争、唯一键约束、SQL 拆分及结果确认。一次批量回调可以包含数条受限 SQL，不保证只发一条 SQL。多分片可以拆事务，不能宣称整批跨事务原子；同 key 的复核与写入必须处于业务定义的一致性边界。

## 批量目标和阈值

减少逐条网络往返、SQL 执行及事务提交。扫描批、配对批、复核批和写入批可分别配置条数、字节、参数预算、最大等待时间及事务时间预算。任一阈值满足即发送，EOF 发送尾批。缓存满优先排空并背压扫描，不丢弃未完成记录。单条超限须明确报错或受限处理。

按目标分片攒批，路由由调用方注入，不假设按 ID 取模，也不逐 key 扫全部分片。无法路由时须另设计批量索引或完整配对策略。路由正确性、错误落片及重复 ID 策略需要业务约定。

## 两个 Memory 指标

1. 当前驻留记录总条数：同 key 两端数据合并后只计一条。
2. 当前各互斥处理状态的条数：之和始终等于驻留总数。

插入增加总量与初始状态计数；迁移时旧状态减一、新状态加一；释放同时扣除总量与终态计数。按分片可筛选，读取使用一致快照；并发迁移与计数更新应原子完成。加载来源是重叠属性，不参与处理状态求和。累计修复次数属于历史指标，不能与驻留量混用。

## 失败、重试和完成

SQL 执行成功不等于事务提交成功。失败批不能整体记成功，提交结果不确定时须重读并幂等确认；已提交分片保留结果。安全游标只越过所有关联分片操作均完成的读取范围，不越过尚未处理的记录。

老表及所有新分片扫描结束，缓存/批次排空且无未决提交或报警，才表示本轮结束。Memory 有界，反向扫描可能再次遇到同 key，允许重新配对及幂等处理；不保留整轮所有 key 去重。

持续并发修改需要明确快照/高水位、版本校验、CDC 或重跑。本轮完成不是完整不停机迁移保证。检查点持久化及崩溃恢复是后续实现，内存状态本身无法提供。

## 补充：单线程可执行顺序的独立演示

[50 条多 shard 演示](../batch-scan-demo.html) 默认一次扫描 50 条，按 5 个 shard 各 10 条分布；每个 shard 依次完整查询、内存比较，再将候选按最多 8 条组成业务事务，插入子批最多 4 条；更新每次只处理 1 条。最后反向逐片扫描，找出仅新表存在的记录并保留报警。

[单线程整体图](../single-thread-state-flow.html) 明确：单线程一次仅执行一个 DB 动作，不并行扫描、查询或修复。当前扫描页有未处理分片/复核批时，优先排空，不获取下一页，不等待其他线程来凑批。页内所有结果完成后才推进安全游标。反向扫描同样先排空当前页再继续。

配对批、复核批、写入子批是不同层次，不能混用完成标记；读完 50 条也不能提前把安全游标记成 50。事务提交结果未知时冻结相关进度，等待业务恢复协议确认。

离线演示覆盖 13 种情况：混合、全部相等、全缺失、全不同、分片倾斜、100 shard 稀疏、候选过期、查询失败、事务回滚、提交响应丢失、事务前取消、只报警及 17+17+16 尾页。累计处理次数包含反向重复遇到记录，不等于唯一 ID 数量；Memory 状态计数是当前驻留量。
